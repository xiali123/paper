## 🎯 核心原则

**"每个问题只被解决一次"** - 通过持续学习机制，确保每次解决复杂问题后，经验都被记录到CLAUDE.md，下次直接复用。

---

## ⚡ 快速检查：是否需要更新文档？

完成任务后，回答以下问题：

1. ⏱️ 解决问题是否耗时超过30分钟？
2. 🆕 是否学习了新技术/新库？
3. 🏗️ 是否进行了架构变更？
4. 🔄 是否是反复出现的问题（3次以上）？
5. ⚠️ 是否采用了非标准的解决方案？

**如果任一答案为"是" → 必须更新文档！**

## 🚀 快速启动：自动化文档更新

### 步骤1: 生成报告模板

```bash
# 问题解决类型
bash scripts/update_claude_docs.sh solution "问题标题"

# 技术集成类型
bash scripts/update_claude_docs.sh integration "技术名称"

# 架构决策类型
bash scripts/update_claude_docs.sh decision "决策标题"
```

### 步骤2: 填写报告内容

脚本会自动生成报告文件，包含标准模板：

- **问题解决** → 记录症状、根本原因、解决方案
- **技术集成** → 记录步骤、遇到的坑、最佳实践
- **架构决策** → 记录背景、决策、后果、替代方案

### 步骤3: 提取经验到CLAUDE.md

根据报告内容，在CLAUDE.md的相应章节中更新：

- 编译问题 → "调试技巧"或"常见任务"
- 新技术集成 → "第三方依赖管理"或创建新章节
- 架构变更 → "核心原则"或"关键约束"

### 步骤4: 提交更新

```bash
git add CLAUDE.md reports/[报告文件].md
git commit -m "docs: 更新CLAUDE.md - [变更摘要]"
```

## 📋 标准模板速查

### 模板1: 问题解决（最常用）

```markdown
### 问题：[简短描述]

**症状**: [错误信息]
**根本原因**: [深入分析]
**解决方案**: [具体步骤]
**预防措施**: [如何避免]

**示例**:
\`\`\`cpp
// ❌ 错误
错误代码

// ✅ 正确
正确代码
\`\`\`
```

### 模板2: 技术集成

```markdown
### [技术]集成经验

**功能**: [作用]
**难度**: [简单/中等/困难]
**时间**: [实际耗时]

**关键步骤**:
1. [步骤1]
2. [步骤2]

**遇到的坑**:
- ❌ [问题] → ✅ [解决]

**最佳实践**:
- ✅ [实践1]
- ✅ [实践2]
```

### 模板3: 架构决策（ADR）

```markdown

**后果**: [影响]

**优点**:
- [优点1]
- [优点2]

**缺点**:
- [缺点1]
- [缺点2]
```

## 🤖 Claude Code工作流程

### 标准流程（完整任务）

```
1. 接收任务
   ↓
2. 查阅CLAUDE.md
   ↓
3. 应用已有经验
   ↓
4. 遇到新问题/学到新经验
   ↓
5. 解决问题
   ↓
6. 运行 update_claude_docs.sh
   ↓
7. 填写报告
   ↓
8. 更新CLAUDE.md
   ↓
9. 提交Git
   ↓
10. 下次直接复用经验 ✅
```

### 快速流程（小任务）

```
1. 完成任务
   ↓
2. 自问："值得记录吗？"
   ↓
3. 如果是，直接在CLAUDE.md中添加
   ↓
4. 提交Git
```

## 💡 实用技巧

### 技巧1: 快速定位问题

**症状**: 编译错误
**查找**: CLAUDE.md中的"调试技巧"章节
**关键字**: 错误代码或文件名

### 技巧2: 学习新技术

**步骤**:
1. 完成集成
2. 运行 `bash scripts/update_claude_docs.sh integration "技术名"`
3. 填写报告
4. 更新CLAUDE.md

### 技巧3: 避免重复错误

**方法**:
1. 遇到错误先搜索CLAUDE.md
2. 如果没有，解决问题后记录
3. 下次直接搜索解决
