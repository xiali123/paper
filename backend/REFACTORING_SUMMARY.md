## 核心问题

### 当前状态
- **文件**: `src/core/main.cpp`
- **行数**: 3890 行
- **问题**:
  - 包含大量硬编码路由注册（37 个）
  - 业务逻辑与框架代码混合
  - 认证系统实现不安全（自定义密码哈希）
  - 数据库配置硬编码
  - 难以维护和扩展

### 目标状态
- **文件**: `src/core/main.cpp`
- **行数**: <300 行
- **改进**:
  - 仅保留应用启动和框架初始化
  - 业务逻辑全部迁移到独立模块
  - 认证系统使用 bcrypt
  - 配置外部化
  - 易于维护和扩展

**任务**:

### 阶段 2: 迁移认证系统（3-4 天）
**目标**: 将所有认证相关代码迁移到 AuthApiModule

**任务**:
1. 增强 AuthApiModule

3. 安全加固

**交付物**:
- 增强的 `AuthApiModule`
- 4 个认证 API 端点
- 安全的密码哈希（bcrypt）

**验收**:
- 用户注册、登录、登出正常
- 密码升级逻辑生效
- 安全测试通过
- main.cpp 减少约 800 行

**风险**: 🔴 高风险 - 认证逻辑变更可能导致用户无法登录

## 风险矩阵

### 高风险项（🔴 6 个）

1. **AUTH-001**: 密码哈希算法变更导致现有用户无法登录
2. **AUTH-002**: Session 存储迁移导致性能下降
3. **DB-001**: 配置文件读取失败导致无法连接数据库
4. **DB-002**: Migration 执行顺序错误
5. **FRAME-001**: 模块依赖顺序错误导致启动失败
6. **SEC-001**: 引入安全漏洞

### 中风险项（🟡 10 个）

1. **AUTH-003**: Token 生成逻辑变更
2. **DB-003**: 连接池配置变更导致连接泄漏
3. **API-001**: JSON 响应格式变化
4. **API-002**: 数据库查询变更导致性能下降
5. **API-003**: 路由迁移后路径冲突
6. **FRAME-002**: ApplicationBootstrap 资源泄漏
7. **COMPAT-001**: API 路径变更
8. **PERF-001**: 模块间通信开销
9. **其他**: 2 个中风险项

## 应急响应计划

### 场景 1: 系统无法启动
**诊断**: 检查日志、配置、数据库连接、模块依赖
**应急**: 切换回旧版本 main.cpp
**时间**: 15 分钟

### 场景 2: 大量用户无法登录
**诊断**: 检查日志、数据库、认证模块
**应急**: 启用双重密码验证、回滚密码验证逻辑
**时间**: 30 分钟

### 场景 3: API 响应时间急剧增加
**诊断**: 检查慢查询日志、模块间通信、缓存
**应急**: 回滚性能回归代码、优化慢查询
**时间**: 1 小时

### 场景 4: 数据损坏或丢失
**诊断**: 检查数据库日志、Migration 记录、备份
**应急**: 停止服务、恢复数据库备份
**时间**: 2 小时
