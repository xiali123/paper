# PaperCrawler 模块化框架设计方案

## 架构师视角：极致解耦的模块化框架设计

**设计目标**：构建一个高度解耦、可扩展、可维护的C++模块化框架，支持插件式架构、事件驱动通信和依赖注入。

---

## 一、当前模块系统评估

### 1.1 现有架构分析

#### ✅ **优势**
1. **清晰的生命周期管理**
   - `IModule`接口定义了标准生命周期：`initialize()` → `start()` → `stop()` → `cleanup()`
   - 状态机明确：`UNLOADED` → `LOADED` → `INITIALIZED` → `STARTED` → `STOPPED` → `FAILED`

2. **分层基类设计**
   - `ServerModuleBase`：提供基础设施模块通用功能
   - `BusinessModuleBase`：提供业务API模块通用功能
   - 模板方法模式确保生命周期钩子正确执行

3. **依赖注入容器**
   - `ServiceContainer`支持三种生命周期：`SINGLETON`、`TRANSIENT`、`SCOPED`
   - 线程安全的服务注册和解析
   - 全局`Services`访问器提供便捷API

4. **事件驱动通信**
   - `EventBusModule`实现发布-订阅模式
   - 支持异步处理、优先级队列、事件持久化
   - `MessageBus`提供模块间直接消息传递

5. **插件系统**
   - `PluginManager`支持动态加载/卸载模块
   - 跨平台支持（Windows DLL、Linux SO、macOS DYLIB）
   - `ModuleRegistry`管理模块元数据和依赖关系

#### ⚠️ **存在的问题**

1. **耦合度问题**
```cpp
// ❌ 当前：业务模块直接依赖具体实现
#include "data/IDatabase.hpp"
#include "data/DatabaseModule.hpp"

class TemplateCrawlerModule {
    std::shared_ptr<IDatabase> database_;  // 硬编码依赖
};
```

2. **缺乏接口抽象**
   - 业务模块直接依赖具体数据库实现
   - 缺乏领域模型抽象（如`ICrawlerService`、`IUserService`）
   - 模块间通信缺乏标准化契约

3. **事件系统职责混乱**
   - `EventBusModule`和`MessageBus`功能重叠
   - 事件类型硬编码在`MessageType`枚举中
   - 缺乏事件版本化和兼容性管理

4. **配置管理分散**
   - 模块配置散落在各处
   - 缺乏统一的配置验证和热重载
   - 环境特定配置（开发/测试/生产）管理不足

5. **测试和模拟困难**
   - 强依赖使得单元测试困难
   - 缺乏Mock/Stubs支持
   - 集成测试环境搭建复杂

### 3.1 增强的服务容器

```cpp
// backend/include/core/EnhancedServiceContainer.hpp
#pragma once
#include "ServiceContainer.hpp"
#include <functional>
#include <vector>
#include <string>

namespace PaperCrawler {

/**
 * @brief 增强的服务容器
 *
 * 新增特性：
 * 1. 装饰器模式支持（AOP）
 * 2. 条件注册（基于环境）
 * 3. 生命周期回调
 * 4. 依赖图可视化
 */
class EnhancedServiceContainer : public ServiceContainer {
public:
    /**
     * @brief 服务装饰器（用于AOP）
     */
    template<typename Interface>
    using Decorator = std::function<std::shared_ptr<Interface>(
        std::shared_ptr<Interface>
    )>;

    /**
     * @brief 带装饰器的服务注册
     */
    template<typename Interface, typename Implementation>
    void registerServiceWithDecorators(
        ServiceLifetime lifetime = ServiceLifetime::SINGLETON,
        std::vector<Decorator<Interface>> decorators = {}
    ) {
        // 先注册基础服务
        registerService<Interface, Implementation>(lifetime);

        // 应用装饰器
        auto instance = resolve<Interface>();
        for (auto& decorator : decorators) {
            instance = decorator(instance);
        }

        // 重新注册装饰后的实例
        registerInstance<Interface>(instance);
    }

    /**
     * @brief 条件注册（基于环境变量）
     */
    template<typename Interface, typename Implementation>
    void registerServiceIf(
        const std::string& envVar,
        const std::string& expectedValue,
        ServiceLifetime lifetime = ServiceLifetime::SINGLETON
    ) {
        const char* actualValue = std::getenv(envVar.c_str());
        if (actualValue && std::string(actualValue) == expectedValue) {
            registerService<Interface, Implementation>(lifetime);
        }
    }

    /**
     * @brief 注册生命周期回调
     */
    template<typename Interface>
    void onResolve(std::function<void(std::shared_ptr<Interface>)> callback) {
        // 实现回调机制
    }

    /**
     * @brief 生成依赖图（DOT格式）
     */
    std::string generateDependencyGraph() const {
        std::stringstream ss;
        ss << "digraph ServiceDependencies {\n";
        ss << "  rankdir=LR;\n";
        ss << "  node [shape=box];\n";

        // 遍历所有服务及其依赖
        auto stats = getStats();
        ss << "  \"Total Services: " << stats.totalServices << "\";\n";

        ss << "}\n";
        return ss.str();
    }
};

} // namespace PaperCrawler
```

### 3.2 统一事件系统

```cpp
// backend/include/core/UnifiedEventBus.hpp
#pragma once
#include <string>
#include <functional>
#include <map>
#include <vector>
#include <memory>
#include <mutex>
#include <any>
#include <chrono>

namespace PaperCrawler {

/**
 * @brief 事件契约（版本化事件）
 */
struct EventContract {
    std::string eventName;
    std::string version;           // 事件版本（如"1.0.0"）
    std::string schema;            // JSON Schema或Protobuf schema
    std::vector<std::string> requiredFields;
    bool requiresAck{false};       // 是否需要确认
    std::chrono::milliseconds ttl{5000};  // 事件TTL

    bool validate(const std::any& data) const {
        // 验证事件数据符合契约
        return true;
    }
};

/**
 * @brief 统一事件总线
 *
 * 整合EventBus和MessageBus功能
 */
class UnifiedEventBus {
public:
    /**
     * @brief 事件处理器
     */
    using EventHandler = std::function<void(const std::any&)>;

    /**
     * @brief 订阅选项
     */
    struct SubscribeOptions {
        bool once{false};
        int priority{0};
        std::string subscriberId;
        std::function<bool(const std::any&)> filter;  // 过滤器
    };

    /**
     * @brief 发布选项
     */
    struct PublishOptions {
        int priority{0};
        bool requireAck{false};
        std::chrono::milliseconds timeout{5000};
        std::map<std::string, std::string> metadata;
    };

    /**
     * @brief 注册事件契约
     */
    void registerContract(const std::string& eventName, const EventContract& contract);

    /**
     * @brief 订阅事件（带契约验证）
     */
    std::string subscribe(
        const std::string& eventName,
        EventHandler handler,
        SubscribeOptions options = {}
    );

    /**
     * @brief 发布事件（带契约验证）
     */
    bool publish(
        const std::string& eventName,
        const std::any& data,
        PublishOptions options = {}
    );

    /**
     * @brief 取消订阅
     */
    void unsubscribe(const std::string& subscriptionId);

    /**
     * @brief 获取事件统计
     */
    struct EventStats {
        uint64_t totalPublished{0};
        uint64_t totalProcessed{0};
        uint64_t totalFailed{0};
        std::map<std::string, uint64_t> byEventType;
    };
    EventStats getStats() const;

private:
    std::map<std::string, EventContract> contracts_;
    std::map<std::string, std::vector<std::pair<EventHandler, SubscribeOptions>>> subscriptions_;
    mutable std::mutex mutex_;
    EventStats stats_;
};

} // namespace PaperCrawler
```

### 3.3 配置管理系统

```cpp
// backend/include/core/ConfigurationManager.hpp
#pragma once
#include <string>
#include <map>
#include <any>
#include <functional>
#include <mutex>
#include "json.hpp"

namespace PaperCrawler {

/**
 * @brief 配置变更监听器
 */
using ConfigChangeListener = std::function<void(const std::string& key, const std::any& oldValue, const std::any& newValue)>;

/**
 * @brief 配置管理器
 *
 * 特性：
 * 1. 分层配置（默认 → 环境 → 命令行）
 * 2. 热重载
 * 3. 配置验证
 * 4. 变更监听
 */
class ConfigurationManager {
public:
    /**
     * @brief 获取单例
     */
    static ConfigurationManager& getInstance();

    /**
     * @brief 加载配置文件
     */
    bool loadFromFile(const std::string& filePath);

    /**
     * @brief 从环境变量加载
     */
    void loadFromEnvironment(const std::string& prefix = "PC_");

    /**
     * @brief 获取配置值
     */
    template<typename T>
    T get(const std::string& key, const T& defaultValue = T{}) {
        std::lock_guard<std::mutex> lock(mutex_);

        auto it = configs_.find(key);
        if (it != configs_.end()) {
            try {
                return std::any_cast<T>(it->second);
            } catch (const std::bad_any_cast&) {
                // 尝试JSON转换
                return convertFromJson<T>(it->second);
            }
        }
        return defaultValue;
    }

    /**
     * @brief 设置配置值
     */
    template<typename T>
    void set(const std::string& key, const T& value) {
        std::lock_guard<std::mutex> lock(mutex_);

        std::any oldValue;
        auto it = configs_.find(key);
        if (it != configs_.end()) {
            oldValue = it->second;
        }

        configs_[key] = value;

        // 触发变更监听器
        notifyChange(key, oldValue, value);
    }

    /**
     * @brief 注册变更监听器
     */
    void onChange(const std::string& key, ConfigChangeListener listener);

    /**
     * @brief 启用热重载
     */
    void enableHotReload(const std::string& configFile);

    /**
     * @brief 验证配置
     */
    bool validate(const std::string& schemaFile);

    /**
     * @brief 获取所有配置
     */
    nlohmann::json exportJson() const;

private:
    ConfigurationManager() = default;

    template<typename T>
    T convertFromJson(const std::any& value) {
        // 实现JSON到T的转换
        return T{};
    }

    void notifyChange(const std::string& key, const std::any& oldValue, const std::any& newValue);

    std::map<std::string, std::any> configs_;
    std::map<std::string, std::vector<ConfigChangeListener>> listeners_;
    mutable std::mutex mutex_;
};

} // namespace PaperCrawler
```

## 五、应用服务层设计（用例层）

```cpp
// backend/include/application/useCases/CrawlPaperUseCase.hpp
#pragma once
#include "domain/ICrawlerService.hpp"
#include "domain/IPaperRepository.hpp"
#include "core/UnifiedEventBus.hpp"
#include <memory>

namespace PaperCrawler::Application {

/**
 * @brief 爬取论文用例
 *
 * 编排领域服务完成业务逻辑
 */
class CrawlPaperUseCase {
public:
    CrawlPaperUseCase(
        std::shared_ptr<Domain::ICrawlerService> crawlerService,
        std::shared_ptr<Domain::IPaperRepository> paperRepository,
        std::shared_ptr<UnifiedEventBus> eventBus
    ) : crawlerService_(crawlerService),
        paperRepository_(paperRepository),
        eventBus_(eventBus) {}

    /**
     * @brief 执行用例
     */
    std::future<Domain::Paper> execute(const std::string& url) {
        return std::async(std::launch::async, [this, url]() {
            try {
                // 1. 发布开始事件
                eventBus_->publish("crawl.started", url);

                // 2. 调用爬虫服务
                auto paperFuture = crawlerService_->crawlPaper(url);
                auto paper = paperFuture.get();

                // 3. 验证并保存
                if (paper.isValid()) {
                    paperRepository_->save(paper);

                    // 4. 发布成功事件
                    eventBus_->publish("crawl.completed", paper);

                    return paper;
                } else {
                    throw std::runtime_error("Invalid paper data");
                }

            } catch (const std::exception& e) {
                // 发布失败事件
                eventBus_->publish("crawl.failed", url);
                throw;
            }
        });
    }

private:
    std::shared_ptr<Domain::ICrawlerService> crawlerService_;
    std::shared_ptr<Domain::IPaperRepository> paperRepository_;
    std::shared_ptr<UnifiedEventBus> eventBus_;
};

} // namespace PaperCrawler::Application
```

```cpp
// ✅ 新设计：依赖抽象
namespace Application {

class TemplateCrawlerModule : public BusinessModuleBase {
public:
    // 构造函数注入依赖
    TemplateCrawlerModule(
        std::shared_ptr<Domain::ICrawlerService> crawlerService,
        std::shared_ptr<Domain::ITemplateRepository> templateRepository,
        std::shared_ptr<UnifiedEventBus> eventBus
    ) : crawlerService_(crawlerService),
        templateRepository_(templateRepository),
        eventBus_(eventBus) {}

    bool initialize() override {
        // 注册路由
        registerRoutes();

        // 订阅事件
        eventBus_->subscribe("template.requested", [this](const std::any& data) {
            handleTemplateRequest(std::any_cast<TemplateRequest>(data));
        });

        return true;
    }

    void registerRoutes() override {
        addRoute("/api/templates", [this](const HttpRequest& req) {
            return handleListTemplates(req);
        });

        addRoute("/api/templates/:id", [this](const HttpRequest& req) {
            return handleGetTemplate(req);
        });

        addRoute("/api/templates/:id/execute", [this](const HttpRequest& req) {
            return handleExecuteTemplate(req);
        });
    }

private:
    HttpResponse handleListTemplates(const HttpRequest& req) {
        auto templates = templateRepository_->findAll();
        return toJsonResponse(templates);
    }

    HttpResponse handleExecuteTemplate(const HttpRequest& req) {
        auto templateId = req.pathParams.at("id");
        auto targetUrl = req.queryParams.at("url");

        // 使用用例执行爬取
        CrawlPaperUseCase useCase(crawlerService_, templateRepository_, eventBus_);
        auto future = useCase.executeWithTemplate(templateId, targetUrl);

        // 异步处理
        return AcceptedResponse();
    }

    std::shared_ptr<Domain::ICrawlerService> crawlerService_;
    std::shared_ptr<Domain::ITemplateRepository> templateRepository_;
    std::shared_ptr<UnifiedEventBus> eventBus_;
};

} // namespace Application
```

```cpp
    std::vector<std::string> dependencies; // 依赖的其他插件

    // 能力声明
    std::vector<std::string> providedServices;  // 提供的服务
    std::vector<std::string> requiredServices;  // 需要的服务
    std::vector<std::string> publishedEvents;   // 发布的事件
    std::vector<std::string> subscribedEvents;  // 订阅的事件

    // 配置
    std::string configSchema;        // 配置JSON Schema
    std::map<std::string, std::string> defaultConfig;

    // 生命周期
    bool autoStart{true};            // 是否自动启动
    int priority{0};                 // 启动优先级（数值越大越优先）

    /**
     * @brief 验证元数据
     */
    bool validate() const {
        return !id.empty() &&
               !name.empty() &&
               !version.empty() &&
               !apiVersion.empty();
    }

    /**
     * @brief 转换为JSON
     */
    nlohmann::json toJson() const {
        nlohmann::json j;
        j["id"] = id;
        j["name"] = name;
        j["version"] = version;
        j["description"] = description;
        j["author"] = author;
        j["license"] = license;
        j["type"] = (type == ModuleType::SERVER) ? "server" : "business";
        j["api_version"] = apiVersion;
        j["min_framework_version"] = minFrameworkVersion;
        j["dependencies"] = dependencies;
        j["provided_services"] = providedServices;
        j["required_services"] = requiredServices;
        j["published_events"] = publishedEvents;
        j["subscribed_events"] = subscribedEvents;
        j["auto_start"] = autoStart;
        j["priority"] = priority;
        return j;
    }
};

} // namespace PaperCrawler
```

## 十一、总结

### 核心优势
1. **极致解耦**：通过依赖倒置和接口隔离，模块间零耦合
2. **高可测试性**：依赖抽象接口，易于Mock和单元测试
3. **灵活扩展**：插件架构支持动态加载和卸载
4. **事件驱动**：统一事件总线实现异步解耦通信
5. **配置管理**：集中化配置支持热重载和环境隔离

### 设计权衡
- **复杂度增加**：更多抽象层次和接口
- **学习曲线**：团队需要理解DDD和Clean Architecture
- **性能开销**：依赖注入和事件总线有一定性能开销

### 适用场景
- ✅ 大型分布式系统
- ✅ 需要长期维护的项目
- ✅ 多团队协作开发
- ✅ 需要频繁扩展功能

### 不适用场景
- ❌ 小型原型项目
- ❌ 性能极致敏感场景
- ❌ 快速实验性项目
